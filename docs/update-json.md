# Update manifest

The app reads `update.json` from the public `main` branch at
`https://raw.githubusercontent.com/flugeru/OrbisExtract/main/update.json`. It checks
once when the view opens and when the user selects **Verificar atualizações** in
**Sobre**. The prompt is optional: **Agora não** dismisses it. No APK or desktop
installer is downloaded or installed by the app.

The public manifest tracks the published release. For 1.0.5, publish the
downloads first, then copy [update-1.0.5.json](update-1.0.5.json) over
`update.json` on `main` to announce the update.

Example:

```json
{
  "version": "1.0.2",
  "releaseNotes": [
    "Nova splash screen no Android com o ícone do OrbisExtract.",
    "Verificação opcional de atualizações em Sobre."
  ],
  "releaseNotesEn": [
    "New Android splash screen with the OrbisExtract icon.",
    "Optional update checks in About."
  ],
  "androidPlayUrl": "https://play.google.com/store/apps/details?id=com.tatsuya.orbisextract",
  "androidGithubUrl": "https://github.com/flugeru/OrbisExtract/releases/latest",
  "windowsUrl": "https://github.com/flugeru/OrbisExtract/releases/latest",
  "linuxUrl": "https://github.com/flugeru/OrbisExtract/releases/latest"
}
```

Android has independent `androidGithub` and `androidPlay` objects, each with
`published`, `version`, `versionCode`, and `url`, plus optional `releaseNotes`
and `releaseNotesEn` for that channel. A channel on a different release never
shows the root changelog. Play builds use a compile-time
channel and always stay on Play, even if Android loses the installer source.
GitHub builds also recognize installation by `com.android.vending`.
A missing or unpublished Play channel never falls back to the GitHub version.
Old manifests remain supported for GitHub and desktop builds.

```json
"androidPlay": {
  "published": false,
  "version": "1.0.5",
  "versionCode": 1051000,
  "url": "https://play.google.com/store/apps/details?id=com.tatsuya.orbisextract"
}
```

Keep `published` false until the release is available to the intended users.
For staged rollouts, let Play handle updates and only announce in this manifest
after full availability. Publish GitHub downloads before changing the legacy
root version, which older clients still use. Supply `androidGithub` with the
actual APK versionCode when publishing to detect same-version rebuilds and avoid
downgrades. Android compares versionCodes; desktop compares semantic versions.
The build number generated by the existing development workflow must not be
confused with the release versionCode: coordinate both and never reuse a code.

Updates are user-confirmed links, not an APK downloader or silent installer.
Play links must match the exact package; GitHub links must point to this repo's
releases over HTTPS. Play is not using Play Core in-app updates: Play itself
handles automatic updates and this app opens the store page.

Keep the existing GitHub signing key for updates to current APK users. The new
Play upload key only authenticates AAB uploads; it is not the Play app signing
key. Cross-channel installation requires matching app signing certificates and
increasing versionCodes. See [play-store.md](play-store.md).
